# 项目总提示词：Cloudflare PWA 消息推送与项目监控平台

你现在是一名资深全栈架构师、Cloudflare 平台工程师和 Vue / TypeScript 开发工程师。

请帮助我从 0 开始开发一套：

**基于 Cloudflare 的个人消息推送与项目运行监控平台。**

项目定位类似于：

* Bark
* ntfy
* Gotify
* Better Uptime
* Sentry Notifications

但不要直接复制这些项目。

本项目需要形成自己的特色：

> 面向开发者的轻量级 Notification Hub + Project Monitor。

核心能力是：

其他项目通过调用本平台 HTTP API，将运行状态、成功消息、错误消息、告警、异常、任务结果等发送到本平台。

平台收到消息以后：

1. 保存消息
2. 实时推送到手机
3. 在 Dashboard 中展示
4. 保留历史记录
5. 后续能够监控项目在线状态
6. 后续能够扩展多个通知渠道

第一阶段不开发原生 iOS App。

移动端采用：

**PWA + Web Push**

用户可以在 iPhone Safari 中访问平台：

```text
https://push.example.com
```

然后：

```text
分享
↓
添加到主屏幕
↓
从桌面启动 PWA
↓
允许通知
↓
接收 iOS Web Push
```

最终希望形成一个长期可维护、可扩展的项目，而不是简单 Demo。

# 四、架构原则

项目必须遵守以下原则。

## 1. Web Push 不是数据源

Push 只负责提醒用户。

真正的数据必须保存在 D1。

正确流程：

```text
收到消息
↓
写入 D1
↓
发送 Web Push
↓
手机收到通知
↓
点击通知
↓
PWA 调 API 获取完整消息
```

即使 Push 失败：

消息也不能丢失。

---

## 2. Notification Channel 必须抽象

禁止将 Web Push 逻辑散落在业务代码中。

定义统一接口：

```ts
interface NotificationChannel {
  send(
    message: NotificationMessage,
    target: NotificationTarget
  ): Promise<NotificationResult>
}
```

第一阶段实现：

```text
WebPushChannel
```

未来应该很容易增加：

```text
APNsChannel
EmailChannel
TelegramChannel
DiscordChannel
SlackChannel
WebhookChannel
SMSChannel
```

业务层不得依赖具体通知渠道。
